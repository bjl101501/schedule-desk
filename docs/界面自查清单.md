# 界面自查清单

> 用途：每一轮交付前按这份清单走一遍，把「用户先发现」变成「自己先发现」。
> 配套脚本 `node build/audit-ui.mjs`（已挂进 `bun run check`）负责静态项，本清单负责交互项。
> 结果记进 `R{n}/checkpoint.md` 的「自查记录」表。

## 一、每轮必跑（约 10 分钟）

| # | 检查项 | 判定方法 | 常见错法 |
|---|---|---|---|
| 1 | 首屏四视图 | 今天 / 列表 / 日历 / 四象限各截一张，看有无错位、遮挡、空态缺失 | 只验了当前视图 |
| 2 | 空态 | 清空数据后逐视图看：是否都有说明与「添加」入口 | 看板原先五列各写「暂无事项」 |
| 3 | 超长文本 | 建一条 40 字标题 + 8 个标签，看是否截断而非撑破 | 单元格不设 `overflow` |
| 4 | 误触路径 | 在勾选框上按下并移动 30px，看是否变成拖拽；点子项标题看是否误标完成 | 整行即开关、`div.chk` 未排除拖拽 |
| 5 | 弹窗文案与动作一致 | 逐个危险操作点开确认框，读按钮是不是这个动作的名字 | 「恢复快照」显示「确认删除」 |
| 6 | 同类操作一致性 | 习惯有编辑按钮，纪念日是不是也有；看板/四象限能不能直接勾完成 | 两套交互模型 |
| 7 | 关闭再打开 | 编辑器/详情反复开关 5 次，看层栈是否残留、草稿是否复位 | `closing` 队列未清理 |
| 8 | 窄窗与宽窗 | 1000 / 1290 / 1440 三个宽度各开一次侧栏，看内容是否被压到不能用 | 只在默认宽度验过 |
| 9 | 撤销链路 | 删除 → Ctrl+Z → 数据回来且 id 不变；再 Ctrl+Shift+Z | 撤销后整表重载、id 变了 |
| 10 | 通知实弹 | 建一条 2 分钟后的日程，读 `wpndatabase.db` 确认文案 | 只信代码里的字符串 |
| 11 | 浮层可见性 | 点开所有下拉框与浮层，确认 `z-index` 高于 `.modal-root`（200）且在视口内 | 浮层被弹窗盖在底下 |
| 12 | 文案巡检 | 全局搜 `任务`（应为「事项」）、反引号、`TODO`、英文残留 | 引导页裸反引号 |

## 二、静态项（`build/audit-ui.mjs` 自动报）

| 规则 | 级别 | 说明 |
|---|---|---|
| 确认按钮文案写死 | 严重 | 共用弹窗必须读 `req.okText`，否则恢复类会显示「确认删除」 |
| `.chk` 未被 `NO_DRAG` 排除 | 严重 | 勾选与拖拽抢同一块区域，勾不上还把卡片拖走 |
| `{@html}` 插入文本字段 | 严重 | 仅白名单静态 SVG 可用；用户输入必须走纯文本 |
| 纯图标按钮缺 `aria-label`/`title` | 提示 | 读屏与悬停无名称提示 |
