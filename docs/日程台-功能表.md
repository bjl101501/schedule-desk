# 日程台 · 功能与操作手册

> 版本 **v2.2.0**（2026-10-30）｜ Windows 桌面应用（Tauri 2 + WebView2）
> 仓库：`D:\OneDrive\Agent\WorkBuddy\scheduledesk\schedule-desktop`
> 数据：本机 JSON 文件，可选 WebDAV 同步；不依赖任何在线服务

这份按「在哪里 → 看到什么 → 能怎么操作 → 会发生什么」写。界面上每一个能点、能拖、能按的地方都在里面。

与旧版单网页的区别：多了托盘常驻、单实例唤起、Windows 原生通知、自动更新、自定义数据目录；
任务时间由「开始 + 计划区间」表达，逾期与提醒共用同一套计算；窗口尺寸、位置、最大化会被记住。

## 1.2 提醒中心

| 区域 / 操作 | 结果 |
|---|---|
| 「已到点提醒」段（红底） | 列出所有到点未确认的提醒，按时间从近到远 |
| 节点标签 | 单次提醒显示「准时」「提前 30 分钟」；艾宾浩斯显示「6/9 · 12 小时」 |
| 行右「知道了」 | 把这个节点标记为已读，这条不再出现（艾宾浩斯只跳过一个节点，不影响后续） |
| 行右「完成」 | 关闭弹窗并直接把任务标记完成 |
| 「24 小时内」段（紫底） | 只读，显示未来 24 小时内会提醒的时间点，最多 12 条 |
| 空态 | 「暂时没有到点的提醒」 |

没有「全部已读」——提醒是一条条确认的，避免一次性清空后漏掉真正该复习的那条。

**提醒跟着日程走**：改日期或改时间（编辑器里改、日历拖到另一天、时间线拖到另一天、看板拖到「本周内 / 更晚」等）时，提醒基准会一起挪到新的日期时间，已读标记随之清空。改成「未安排」则暂时收起提醒，重新排上日期会自动接回。

**系统通知**（桌面版）：到点由 Windows 原生通知弹出，不打开窗口也会提醒。

- 通知常驻在屏幕右下角，直到你手动关闭或进入操作中心，不会几秒后自己消失；带应用图标；
- 标题就是日程标题，正文按类型生成：
  - 提前：`将在 15:00 开始，还有 30 分钟`
  - 开始：`现在开始，预计 45 分钟`
  - 结束前：`还有 10 分钟结束（16:00）`
  - 到结束点：`已到结束时间（16:00），还没完成吗`
  - 逾期：`已在 16:10 逾期，尚未完成`
  - 错过（软件没开）：聚合成一条 `错过 3 条提醒`，正文列前三条时间与标题
  - 艾宾浩斯：`复习提醒 · 第 6/9 次（12 小时）`
- 勾了「稍后提醒」的，主提醒发出 5 分钟后再补一条

# 四、任务状态与逾期判定

所有视图（列表、卡片、看板、详情、今日面板、统计、通知）都读同一份判定。

## 4.1 用到的字段

开始日期、开始时间（可空）、预计用时（可空）、计划（开关）、结束日期、结束时间。

## 4.2 结束时刻怎么算

| 组合 | 结束时刻 |
|---|---|
| 计划 + 结束时间 | 结束日期 + 结束时间 |
| 计划 + 无结束时间 | 结束日 24:00 |
| 无计划 + 有开始时间 + 有预计用时 | 开始 + 预计用时 |
| 无计划 + 有开始时间 + 无预计用时 | 开始时刻本身（到点即逾期） |
| 无开始时间（全天） | 计划：结束日 24:00；否则当天 24:00 |
| 计划与预计用时都有 | 取两者中较晚的那个 |

## 4.3 状态

| 条件 | 状态 | 文案 |
|---|---|---|
| 现在 < 开始，提前提醒到点 | 即将开始 / 即将逾期 | 有预计用时→即将开始；否则即将逾期 |
| 开始 ≤ 现在 ≤ 结束，非全天 | 进行中 | `进行中 · 剩余 3 小时` |
| 开始 ≤ 现在 ≤ 结束，全天 | 进行中 | `全天 · 进行中` |
| 现在 > 结束 | 逾期 | `已逾期 2 天`（取最大单位） |
| 已完成 | 无状态 | 显示完成时间 |

## 4.4 子项

- 子项按自己的排期判断：过了那段排期最后一天仍未勾选，显示「子项逾期」。
- 父任务不因子项未完成而提前逾期。
- 子项完成时间：普通子项只写时刻；计划子项早于/晚于自己那段排期时写「提前 X 完成」「逾期 X 后完成」。

# 六、新建 / 编辑日程

## 6.1 表单结构

顶部是标题与备注，下面是 **6 张分组卡片**，卡片之间有底色与描边区分，不再是「一片输入框」：

| 卡片 | 字段 |
|---|---|
| 时间安排 | 开始日期、开始时间、预计用时、计划（结束日期/时间）、重复 |
| 归属与时长 | 清单、预计时长 |
| 拆分 | 子项列表、子项模板 |
| 优先级 | 优先级、四象限 |
| 标签 | 已选标签、标签输入、选已有 |
| 提醒 | 提醒方式、提醒时机 / 复习节点、基准时间 |

输入框（白底、有描边）、胶囊按钮（浅底、无描边）、下拉选择（带箭头）三种形态一眼可分；深浅主题都单独校过色。

所有输入框都关闭了自动填充（`autocomplete=off` + 随机字段名 + 关闭拼写检查），不会弹出以前输入过的历史。

## 6.2 开始日期 / 时间（自绘面板）

| 控件 | 操作 | 结果 |
|---|---|---|
| 开始日期 | 点字段 | 弹出月历：今天 / 明天 / 下周一 快捷按钮，右上「清除」变未安排 |
| 日期面板 | `‹` `›` | 按月翻页；点某天即选中并关闭 |
| 时间 | 点字段 | 弹时间面板：左列小时、右列分钟，下方常用时间（09:00 / 12:00 / 18:00 等） |
| 时间面板 | 点小时 | 只改小时，面板保持展开 |
| 时间面板 | 点分钟 | 写入并关闭 |
| 时间面板 | 点面板外 | 按当前选择提交（不会白选） |
| 时间面板 | 「清除」 | 变回全天日程 |

时间留空即全天。字段里显示「留空默认为全天」，不再显示「全天」两个字冒充已填值。
选择面板与日历共用同一套外壳、圆角与配色；时间两列连成一块，不画分隔线、不显示滚动条。

## 6.3 计划（跨多天）

勾选「计划」后出现结束日期与结束时间。

- 不勾 = 只占开始日当天；
- 勾上并选 10/30 = 从开始日到 10/30 都算进行中，之后才逾期；
- 改开始日期时计划区间整体平移，跨度不变；
- 子项填的「天」只用于排期，不再反向撑大计划；超出时提示「子项排了 6 天，超出 1 天」；
- 提示条显示「计划 5 天：10/26 – 10/30 · 3 个阶段」。

## 6.4 标签

| 操作 | 方式 | 结果 |
|---|---|---|
| 添加 | 输入后按 **空格 / 回车 / 逗号** | 一次可加多个；拼音输入法回车确认时不会误加 |
| 批量粘贴 | 粘贴「工作 会议 客户」 | 自动拆成三个标签 |
| 移除 | 点标签上的 × | 立即移除 |
| 选已有 | 右侧「选已有」按钮（84px 固定宽） | 展开多选面板（最宽 260px），勾选即加入，再点取消；按钮上显示已选个数 |
| 退格 | 输入框为空时按退格 | 删掉最后一个标签 |

## 6.5 清单

输入框 + 「选已有」+「＋ 新建清单」。选已有是圆点单选，选完自动收起并写进输入框；「＋ 新建清单」清空输入框让你起新名字。

## 6.6 预计时长

数字输入 + 「分钟 / 小时」切换。入库一律按分钟；整小时进编辑器时按小时显示（120 → 2 小时），切换单位会换算已填数值。

留空 = 全天日程，输入框占位写「留空默认为全天」，不再用 45 这种数字冒充默认值。

## 6.7 提醒

| 提醒方式 | 出现什么 | 说明 |
|---|---|---|
| 不提醒 | 无 | — |
| 单次提醒 | 提醒时机 chips：准时 / 提前 5 / 10 / 30 分钟 / 1 小时 / 1 天 | 选一个；下方可勾「稍后提醒」与「结束提醒」 |
| 结束提醒 | 与提醒时机共用同一套提前量 | 仅在能算出明确结束时刻时可勾：计划且填了结束时间，或有开始时间 + 预计用时 |
| 艾宾浩斯 | 9 个节点开关 + 基准时间 | 准时 / 5 分钟 / 30 分钟 / 12 小时 / 1 / 2 / 4 / 7 / 15 天，可只留需要的节点 |

**基准时间跟随日程**：只要上面填了开始日期，基准时间就取「日期 + 时间（没填时间用 09:00）」，以只读形式展示，不需要手填；只有把日期清空（未安排）时才出现手动输入框。保存时优先取上面的日期时间。

节点显示统一为「第 n/N 次」，N 是实际选中的节点数，不是固定 9。

## 6.8 用已有日程填充（模板）

新建弹窗标题右侧有「用已有日程填充」。点开是一个可按关键词搜索的列表，列出所有已有日程，每行显示标题、清单、时长/子项数。

选中后会把**结构**搬过来：清单、标签、优先级、四象限、预计用时、子项（含天数）、计划跨度、提醒方式与节点、稍后提醒/结束提醒开关。

**不会搬**：标题、备注、开始日期、开始时间 —— 这些是这次要新填的内容，保持你当前输入的值。

## 6.9 拆分（子项）

| 操作 | 方式 | 结果 |
|---|---|---|
| 添加子项 | 点「＋ 添加子项」 | 新增一行：标题 + 分钟数 + 天数（勾了「多天」才出现）+ 删除 × |
| 删除子项 | 点行尾 × | 移除该行 |
| 改标题 / 时长 | 直接改输入框 | 实时更新合计 |
| 用模板 | 点「作业分科 / 健身分部 / 学习分段 / 家务分工」 | 一键填入预设子项 |
| 用作预计时长 | 合计不为 0 时出现 | 把子项合计填进预计时长 |

## 6.10 快速添加（智能识别）

侧栏顶部「＋ 添加日程」或 `Ctrl + K` 打开。一行文字里可以直接写日期、时间、标签、优先级，剩下的才是标题。

| 能识别 | 例子 |
|---|---|
| 相对日期 | 今天 / 明天 / 后天 / 大后天 / 昨天 |
| 几天后 | 3 天后 / 2 周后 |
| 星期 | 周三 / 下周一 / 下下周五 |
| 具体日期 | 10月28日 / 10/28 / 2026-10-28 |
| 时间 | 下午3点 / 15:30 / 晚上8点半 |
| 标签 | `#工作` `#会议`（可多个） |
| 优先级 | `!p1` 或 `!1` |

输入时下方实时预览解析结果；点「更多选项」把已解析的内容带进完整编辑器继续补细节。输入框默认是空的，不会回填上次的内容。

## 6.11 底部按钮

| 按钮 | 结果 |
|---|---|
| 删除 | 二次确认后删除（编辑已有任务时才有） |
| 取消 | 关闭，不保存 |
| 添加任务 / 保存修改 | 校验标题 → 写入 → 同步（若配了 WebDAV）→ 刷新视图 |
| 返回（‹） | 从编辑器退回详情 |

## 6.12 跨天日程怎么加（7 天的项目拆成 2/3/1/1 天）

例：课程论文，10/26 开始，分调研 2 天、写作 3 天、修改 1 天、提交 1 天。

1. 新建日程，标题「课程论文」，**开始日期**选 10/26
2. 勾上**「计划」**，结束日期选 11/1
3. 在「拆分」里加 4 个子项：调研 / 写作 / 修改 / 提交
4. 每个子项后面的「天」分别填 2、3、1、1
5. 保存后：
   - 编辑区实时提示「占 7 天：10/26 – 11/1 · 4 个阶段」
   - 详情显示「跨度 7 天 · 10/26 – 11/1 · 4 个阶段」，每个子项右侧标出它占的日期
   - 日历里经过的每一天各占一格：10/26 是「课程论文」，10/27 起是「├ 第2天 课程论文」直到「├ 第7天」
   - 时间线上是一根 7 天色带，内部分成 4 段

规则：

- 不勾「多天」就没有跨天，即使子项填了天数也按 0 处理
- 子项天数从开始日依次往后排，不填天数就不占日子（只当时长拆分）
- 计划跨度只由结束日期决定；子项天数超出时提示「超出 N 天」，不自动改结束日
- 子项天数存在任务的「拆分」字段里，不新增数据列

# 八、四象限

| 操作 | 方式 | 结果 |
|---|---|---|
| 打开详情 | 单击卡片 | 右侧面板打开；勾选完成、改字段都在面板里 |
| 完成 | 先打开详情，点顶部大勾选框 | 卡片本身没有勾选框，避免误点 |
| 换象限 | 按住卡片拖到另一个象限的空处 | 自动改写「重要 / 紧急」并同步 |
| 新建 | 用侧栏「＋ 添加日程」或 `N` | 新建时设好两个开关就会自动归位 |

顶部横幅：待办总数、重要项数、紧急项数。每格左上角是罗马数字 Ⅰ–Ⅳ + 象限名 + 一句行动建议，右上角显示「N 项 · 百分比」。

坐标：**横轴向右＝更紧急，纵轴向上＝更重要**。

| 位置 | 象限 | 含义 | 建议 |
|---|---|---|---|
| 左上 | Ⅰ 重要 · 不紧急 | 决定长期 | 计划做 |
| 右上 | Ⅱ 重要 · 紧急 | 必须现在处理 | 立即做 |
| 右下 | Ⅲ 不重要 · 紧急 | 别人的急事 | 少做或转交 |
| 左下 | Ⅳ 不重要 · 不紧急 | 消磨时间 | 不做 |

已完成的任务不进四象限。

## 15.4 自动更新

设置 →「检查更新」→ 拉取 GitHub Release：

1. 显示「已是最新」或新版本号 + 更新说明；
2. 选「下载并安装」会下载安装包、替换当前 exe 并自动重启；
3. 若当前不是发布版（例如测试目录），会提示无法自替换，需手动替换。

## 15.5 便携与隔离

支持命令行 `--data-dir <路径>` 临时指定数据目录，用于：多套数据互不干扰、把数据放在同步盘、测试时不碰真实数据。

# 十八、数据表结构

# 十九、性能与测试

| 项 | 值 |
|---|---|
| 前端源码 | CSS 约 1930 行 / 约 110 KB；JS 11 个模块 / 约 7500 行 / 约 345 KB |
| 桌面端 | Rust 9 个文件 / 1992 行 |
| 构建产物 | 前端内联后约 470 KB；exe 约 4.1 MB |
| 定时器 | 状态刷新 1 个（15 秒）＋ 时钟 1 个（15 秒对齐分钟） |
| 列表渲染 | 首屏 60 条 + 分批追加；状态刷新不重建 DOM，滚动位置与展开状态不丢 |
| 本地缓存 | 260ms 合并写入，避免连续操作反复序列化 |
| 自动化回归 | 35 组检查 + 13 条状态样本，覆盖状态矩阵、日期/时间面板、标签、模板、快速添加、详情文案；0 偏差、0 JS 异常 |
| 桌面验收 | 二次启动唤起（约 0.08 秒、单进程）、通知 +13 秒仍在屏、稍后提醒补发、更新检查返回真实 Release |
